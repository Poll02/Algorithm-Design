

## Problem 2: Dynamic Programming (Rome to Paris)

**1. Recurrence Relation**
Let $C(i)$ be the minimum cost to travel the first $i$ miles.
To simplify the boundaries, we define the cost of the starting point (Rome) and the destination (Paris) as $0$: $A[0] = 0$ and $A[n] = 0$.
The base case is:
$C(0) = 0$

The recurrence relation for $i > 0$ is:
$$C(i) = A[i] + \min_{1 \le j \le k, \\ i-j \ge 0} \\{ C(i-j) \\}$$
*Explanation:* The cost to reach hotel $i$ is the fixed cost of staying at hotel $i$ ($A[i]$) plus the minimum cost of reaching any valid previous hotel within the maximum daily driving distance $k$.

**2. Pseudocode**
```text
Function MinHotelCost(A, n, k):
    A[0] = 0
    A[n] = 0 
    
    C = array of size n+1 initialized to +infinity
    C[0] = 0
    
    For i from 1 to n:
        For j from 1 to k:
            If i - j >= 0:
                If C[i-j] + A[i] < C[i]:
                    C[i] = C[i-j] + A[i]
                    
    Return C[n]

```

**3. Time Complexity**
The algorithm uses two nested loops. The outer loop runs $n$ times. The inner loop runs at most $k$ times for each $i$. Inside the inner loop, all operations (addition, comparison, assignment) take $O(1)$ time. Therefore, the overall time complexity is $O(nk)$.

## Problem 3: NP-Completeness (Class Scheduling)

**1. Appartenenza a NP (Class scheduling in NP)**

* **Witness (Certificato):** Un array $t$ di dimensione $n$, dove l'elemento $i$-esimo rappresenta l'ID della stanza (da $1$ a $k$) assegnata alla classe $i$. La dimensione del certificato è polinomiale limitata.
* **Verificatore:** Un algoritmo che controlla ogni coppia di classi $(i, j)$ per verificare se $t[i] = t[j]$ (ossia, se condividono la stessa stanza). In tal caso, verifica che non ci sia intersezione tra i loro time slot $S_i$ e $S_j$. Poiché ci sono al massimo $O(n^2)$ coppie da controllare, la verifica avviene interamente in tempo polinomiale.

**2. NP-Hardness (Riduzione k-coloring -> Class scheduling)**
Data un'istanza di k-coloring con un grafo $G=(V,E)$ e un intero $k$, costruiamo un'istanza di Class scheduling nel seguente modo:

* **Classi e Stanze:** Le $|V|$ classi corrispondono ai vertici del grafo. Le $k$ stanze corrispondono ai $k$ colori disponibili.
* **Time Slots:** Per ogni singolo arco $e = (u,v) \in E$, creiamo un istante temporale univoco $t_e$. Aggiungiamo questo specifico istante $t_e$ ai time slot di entrambe le classi associate, $S_u$ e $S_v$.

*Dimostrazione costruttiva:*

* $(\implies)$ Se il grafo $G$ possiede una $k$-colorazione valida, nessun arco connette due nodi dello stesso colore. Assegnando le classi alle stanze in base al colore dei rispettivi vertici, due classi nella stessa stanza non condivideranno mai un istante temporale $t_e$ (il quale esiste solo se c'è un arco tra di loro). Di conseguenza, non c'è alcuna sovrapposizione e il Class scheduling è risolto.
* $(\impliedby)$ Se le classi possono essere assegnate a $k$ stanze senza alcuna sovrapposizione temporale, significa che due classi nella stessa stanza non hanno mai istanti $t_e$ in comune. Questo implica che nel grafo originale non esiste l'arco $e$ tra quei due nodi. Sostituendo le stanze con i colori, otteniamo una $k$-colorazione perfettamente valida per il grafo $G$.
